# Пошаговая диагностика приложения на сервере

Выполняй в консоли сервера (или с Mac после `ssh root@130.49.149.162`).

## Шаг 1: Приложение вообще запущено?

После деплоя и `pm2 start` проверь:

```bash
curl -s http://127.0.0.1:3000/api/ping
```

Ожидаем: `{"ok":true,"step":"app",...}`  
Если таймаут или ошибка — приложение не слушает порт 3000 (не запустилось или упало). Смотри: `pm2 logs like-that`.

---

## Шаг 2: Есть ли .env и DATABASE_URL?

```bash
cd /var/www/like-that
test -f .env && echo "Файл .env есть" || echo "Файла .env нет"
grep -q "DATABASE_URL" .env && echo "DATABASE_URL задан" || echo "DATABASE_URL не задан"
```

---

## Шаг 3: Работает ли база данных?

```bash
curl -s http://127.0.0.1:3000/api/health/db
```

Ожидаем: `{"ok":true,"step":"db",...}`  
Если `{"ok":false,"error":"..."}` — смотри `error` и `hint` в ответе (pgbouncer, allow list, и т.д.).

---

## Шаг 4: Полная проверка (админ health)

```bash
curl -s http://127.0.0.1:3000/api/admin/health
```

Там проверки: БД, env, загрузки.

---

## Запуск без БД

Приложение может **запуститься** без рабочей БД (порт 3000 откроется).  
`/api/ping` будет отвечать.  
Страницы `/` и `/admin` при обращении к API вернут ошибки, если БД недоступна.

Чтобы БД не мешала старту, можно временно переименовать `.env` в `.env.bak` и в `pm2 restart like-that` — тогда используется заглушка, приложение стартует; `/api/health/db` вернёт «DATABASE_URL не задан».
