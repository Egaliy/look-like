1. ✅ Все изменения закоммичены и запушены в GitHub
2. ✅ Настроен GitHub Actions workflow для автоматического деплоя
3. ✅ Workflow будет автоматически запускаться при каждом push в ветку `main`

## 🔧 Настройка Secrets в GitHub

Для работы автоматического деплоя нужно настроить секреты в GitHub:

1. Перейдите в ваш репозиторий на GitHub
2. Откройте **Settings** → **Secrets and variables** → **Actions**
3. Добавьте следующие секреты:

### Обязательные секреты:

- **`VPS_HOST`** - IP адрес или домен вашего VPS сервера
  - Пример: `123.45.67.89` или `example.com`

- **`VPS_USER`** - имя пользователя для SSH подключения
  - Пример: `root` или `deploy`

- **`VPS_SSH_KEY`** - приватный SSH ключ для подключения к серверу
  - Скопируйте содержимое вашего приватного ключа (обычно `~/.ssh/id_rsa` или `~/.ssh/id_ed25519`)
  - Включайте весь ключ, включая строки `-----BEGIN ... KEY-----` и `-----END ... KEY-----`

### Опциональные секреты:

- **`VPS_PROJECT_PATH`** - путь к проекту на сервере (по умолчанию `/var/www/like-that`)
  - Если ваш проект находится в другом месте, укажите полный путь

## 🚀 Что происходит при деплое

При каждом push в ветку `main` автоматически выполняется:

1. Подключение к серверу по SSH
2. Обновление кода из репозитория (`git pull`)
3. Установка зависимостей (`npm ci`)
4. Генерация Prisma клиента (`prisma generate`)
5. Применение миграций базы данных (`prisma migrate deploy`)
6. Сборка приложения (`npm run build`)
7. Перезапуск приложения через PM2 (`pm2 restart like-that`)

## 📋 Проверка статуса деплоя

1. Перейдите в ваш репозиторий на GitHub
2. Откройте вкладку **Actions**
3. Вы увидите все запуски workflow
4. Кликните на последний запуск, чтобы увидеть детали

## ⚠️ Важные замечания

1. **Путь к проекту**: Убедитесь, что путь к проекту на сервере правильный. По умолчанию используется `/var/www/like-that`, но вы можете изменить его через секрет `VPS_PROJECT_PATH`.

2. **PM2**: Убедитесь, что на сервере установлен PM2:
   ```bash
   npm install -g pm2
   ```

3. **Права доступа**: Убедитесь, что пользователь SSH имеет права на:
   - Выполнение git команд
   - Запуск npm команд
   - Управление PM2 процессами

4. **Переменные окружения**: Убедитесь, что на сервере есть файл `.env` с необходимыми переменными:
   - `DATABASE_URL`
   - `NEXTAUTH_URL`
   - `NEXTAUTH_SECRET`
   - И другие необходимые переменные

5. **Первая настройка**: При первом деплое убедитесь, что:
   - Проект уже клонирован на сервере
   - Настроен PM2 процесс с именем `like-that`
   - Или workflow создаст его автоматически при первом запуске

## 🔍 Отладка

Если деплой не работает:

1. Проверьте логи в GitHub Actions
2. Убедитесь, что все секреты настроены правильно
3. Проверьте SSH подключение вручную:
   ```bash
   ssh -i ~/.ssh/your_key user@your_server
   ```
4. Проверьте, что путь к проекту правильный
5. Убедитесь, что PM2 установлен и работает

## 📝 Пример настройки PM2 на сервере

Если PM2 еще не настроен, выполните на сервере:

```bash
cd /var/www/like-that  # или ваш путь к проекту
npm install -g pm2
pm2 start npm --name "like-that" -- start
pm2 save
pm2 startup  # для автозапуска при перезагрузке сервера
```
